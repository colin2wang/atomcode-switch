# Release v0.1.7

## Added

- **Auto-update on switching to an expired account** — New setting **"Auto-open update window when switching to an expired account"** (default: off). When enabled and you switch to an account whose reset time has already passed, the app automatically opens the Update Account Info window, runs `atomcode login` to fetch fresh output, parses it, and applies the update — all in one step.
- **New `is_account_expired()` helper** — Determines account expiry from the reset time, supporting both the current `YYYY-MM-DD HH:MM` format and the legacy `HH:MM` fallback, consistent with the card countdown logic.
- **New `auto_update_on_switch_expired` config field** — Persisted in `atomcode-accounts.yaml` with `#[serde(default)]`, so existing config files remain compatible (defaults to `false`).

## Changed

- **Auto parse after fetch in the update window** — Fetching login info (on window open, on Re-fetch, or when triggered by an expired-account switch) no longer waits for the user to click Parse and Update. Once the fetch completes, the output is parsed and applied automatically; on success the window closes by itself.
- **Failed parse keeps the window open** — If parsing/updating fails (manually or automatically), the Update Account Info window stays open, the error is shown in the status bar, and the user can click Re-fetch (which again auto-parses) or paste the output and retry Parse and Update.

## Settings

- The new checkbox lives in **Settings → Auto-Switch Rules** and is saved with the rest of the settings on OK.
- Localized in both zh_cn and en_us locales.
