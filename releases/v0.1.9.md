# Release v0.1.9

## Fixed

- **Export is now atomic and reports failures** — `handle_export` uses `io::atomic_write_text` (`.tmp` → `.bak` → rename) instead of `std::fs::write`; YAML serialization and write errors surface via the new `status_export_failed` message instead of silently showing "Export succeeded".
- **Corrupt accounts YAML no longer clears accounts** — `load_accounts_from` returns `Result<AppConfig, String>` and all three call sites (settings browse, settings confirm, export conflict check) surface a localized error. Switching to a data directory with a corrupt or valid-but-empty accounts file aborts the import and keeps the current accounts instead of silently emptying them.
- **`/login` username matching prevents cross-account writes** — when a login username is recognized but matches no stored account, parsing returns an error (`status_login_user_unmatched`) instead of silently applying plan/usage to the active account. Added Chinese username markers (`已登录为` / `登录为` / `当前用户`) alongside `logged in as `.
- **Auto-fetch captures complete output** — added `剩余` / `Usage` / `到期时间` early-exit keywords so pure-English or "剩余"-first output no longer waits unnecessarily; the stdout/stderr flush window is no longer zero on early exit or process kill, preventing truncated output.
- **Sort label matches behavior** — `sort_none` is now "按名称 / By name" (the `None` mode has always sorted by name).

## Changed

- **Four-level account badge colors** — `Normal` / `Expiring` / `Expired` / `Invalid` now render as badges with distinct backgrounds and foregrounds, unified to the GitHub palette (`STATUS_OK_*`, `STATUS_EXPIRING_*`, `STATUS_EXPIRED_*`, `STATUS_INVALID_*`). Card borders, progress bars and the reset countdown use the same semantic colors; the redundant `●` prefix was removed from badge labels. The expiring threshold is now a shared constant (`EXPIRING_SOON_SECS`) used by both the expiry classification and the countdown.
- **Card border theme colors** — cards use a white background with a state-themed border: active/selected = red (`GITHUB_RED`, overrides the state color), Normal = green, Expiring = blue, Expired = yellow, Invalid = red. Badges, progress bars and countdown text follow the same per-state theme (expiring blue, expired yellow).
- **Sub-window icon** — the "Update Account Info" viewport reuses the main window icon via a shared `Arc<IconData>` held on the app state.
- **Update-window polish** — the bottom action bar has a white fill with a top divider, symmetric margins and vertically centered, consistently sized buttons. A successful parse keeps the window open for 3 seconds and replaces "Parse & Update" with a live closing countdown; both parse paths share the delay and repaint more frequently during the countdown.
- **i18n cleanup** — removed the dead `status_fetched` key; added `status_export_failed`, `status_accounts_file_invalid`, `status_login_user_unmatched`, `dialog_import_failed_title`, `update_closing` to both locales and to `ALL_KEYS`.

## Added

- **Badge color unit test** — verifies the four visual states have distinct background and foreground colors.

## Upgrade notes

No action required. Existing config files remain compatible; no new persisted fields were introduced.
