# Release v0.1.8

## Added

- **Card list sorting** — New card-list ordering option in **Settings** (persisted as `sort_mode` in `atomcode-accounts.yaml` with `#[serde(default)]`, defaults to `None` so existing configs stay compatible). Three modes: **Unsorted** (by name), **Reset Time** (by next reset time, earliest first), and **Window Remaining** (by remaining usage window, soonest first). Localized in both zh_cn and en_us locales.
- **New `SortMode` enum** — Defined in `models.rs` (`#[derive(Default)]` = `None`), with `sort_accounts()` in `ui.rs` and a `parse_reset_datetime()` helper (in `ops/time_utils.rs`) that reuses the `YYYY-MM-DD HH:MM` / legacy `HH:MM` reset-time parsing consistent with the rest of the app.
- **Dedicated update-window message area** — New `UpdateMessage { kind, text }` struct and `UpdateMessageKind::{Info, Success, Error}` enum, with `set_update_message()` / `clear_update_message()` helpers on `App`, so the Update Account Info window shows structured results (blue Info / green Success / red Error) instead of only writing to the main status bar.
- **Unit tests + CI** — Added `#[cfg(test)]` coverage for parsing, time, config compatibility and i18n alignment; added a GitHub Actions workflow (`fmt --check` / `clippy -D warnings` / `check` / `test`).

## Changed

- **Parse-result UX in the update window** — On success the window now shows a green "Parsed successfully" message and closes itself after a short delay; on failure it shows a red "Parse failed — window and original content are kept" title with a hint to Re-fetch or edit-and-retry, keeping both the window and the original text box content. Errors are also mirrored to the main status bar via `set_update_message()`.
- **No-field-recognized guard** — When `parse_login_output_and_update` recognizes none of the fields (plan / usage / remaining days / reset time), it returns `Err` without writing to disk or updating `last_updated`; the user sees a localized "No account info recognized…" message.
- **Auto-fetched status shown inline** — After a successful auto-fetch, an Info (blue) message is shown in the update window ("Fetching…" / "Fetched") rather than only updating the main status bar.
- **`build.ps1` hardened** — Added safety checks to the release packaging script.
- **Data-safety hardening** — Config and `auth.toml` writes are now atomic (`.tmp` → `.bak` → rename); a malformed accounts YAML is backed up to `*.bak` and reported in the status bar instead of being silently reset. All persistent structs use struct-level `#[serde(default)]` so older configs keep loading. `save_config()` now returns `Result` and failures surface to the UI.
- **Unified time parsing** — New `time_utils::parse_reset_datetime()` is the single source of truth for expiry, card countdown and sorting; legacy `HH:MM` values are no longer misjudged as stale. All timezone conversions use DST-safe handling, eliminating `unwrap()` panic paths.
- **Transactional `/login` parsing** — New pure `login_parser` collects `ParsedFields` before applying anything (zero recognized fields = no write). Added English `Usage: N%` support and strict HH:MM validation; fixed a UTF-8 byte-slice panic risk.
- **Robust update state machine** — Fetch results are generation-guarded so closing/cancelling the window discards stale background results; `atomcode login` output is captured on separate stdout/stderr threads with a real timeout and early-exit; execution errors go to the error message area instead of the parser. Repeated clicks no longer spawn duplicate processes.
- **Account-info freshness** — Newly imported accounts are marked `Unknown` and excluded from auto-switch until their info is refreshed via `/login`. Auto-switch now requires the candidate to be below the threshold and at least 5% better than the current account (hysteresis), and programmatic switches no longer pop the update window.
- **UI/i18n/theme cleanup** — All user-visible strings are localized (added key-alignment test and canonical `ALL_KEYS`); export default filename is `atomcode-accounts.yaml`; card rendering uses deferred actions instead of cloning accounts each frame; colors and button styles are centralized in `theme.rs`; ICO decode failures degrade gracefully.

## Upgrade notes

No action required. Existing config files remain compatible. If a config file was previously corrupted, it will be backed up as `*.bak` on next launch.
