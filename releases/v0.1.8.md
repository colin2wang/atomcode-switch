# Release v0.1.8

## Added

- **Card list sorting** — New card-list ordering option in **Settings** (persisted as `sort_mode` in `atomcode-accounts.yaml` with `#[serde(default)]`, defaults to `None` so existing configs stay compatible). Three modes: **Unsorted** (by name), **Reset Time** (by next reset time, earliest first), and **Window Remaining** (by remaining usage window, soonest first). Localized in both zh_cn and en_us locales.
- **New `SortMode` enum** — Defined in `models.rs` (`#[derive(Default)]` = `None`), with `sort_accounts()` in `ui.rs` and a `parse_reset_time_for_sort()` helper that reuses the `YYYY-MM-DD HH:MM` / legacy `HH:MM` reset-time parsing consistent with the rest of the app.
- **Dedicated update-window message area** — New `UpdateMessage { kind, text }` struct and `UpdateMessageKind::{Info, Success, Error}` enum, with `set_update_message()` / `clear_update_message()` helpers on `App`, so the Update Account Info window shows structured results (blue Info / green Success / red Error) instead of only writing to the main status bar.

## Changed

- **Parse-result UX in the update window** — On success the window now shows a green "Parsed successfully" message and closes itself; on failure it shows a red "Parse failed — window and original content are kept" title with a hint to Re-fetch or edit-and-retry, keeping both the window and the original text box content. Errors are also mirrored to the main status bar via `set_update_message()`.
- **No-field-recognized guard** — When `parse_login_output_and_update` recognizes none of the fields (plan / usage / remaining days / reset time), it returns `Err` without writing to disk or updating `last_updated`; the user sees a localized "No account info recognized…" message.
- **Auto-fetched status shown inline** — After a successful auto-fetch, an Info (blue) message is shown in the update window ("Fetching…" / "Fetched") rather than only updating the main status bar.
- **`build.ps1` hardened** — Added safety checks to the release packaging script.
